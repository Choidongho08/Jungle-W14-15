## 1. 학습 루프: 네 단계와 반복 구조

### 1.1 한 미니배치에서 일어나는 일

과제 문서 8장의 규칙(이 4줄은 과제 문서에 이미 있는 것이다):

```python
logits = model.forward(x_batch, train=True)      # 1. Forward
loss = criterion.forward(logits, y_batch)        # 2. Loss
model.backward(criterion.backward())             # 3. Backward
optimizer.update(model.params, model.grads)      # 4. Update
```

핵심 의존 관계:

| 단계 | 읽는 것 | 만드는 것 |
| --- | --- | --- |
| Forward | `params`(W, b), 입력 | logits, 각 layer의 캐시(Affine의 `x`, ReLU의 mask) |
| Loss | logits, 정답 | 스칼라 loss, softmax 확률(backward용 캐시) |
| Backward | 위에서 저장한 캐시 | `grads` (params와 같은 key, 같은 shape) |
| Update | `params`, `grads` | **갱신된 `params`** (다음 미니배치의 Forward가 이를 사용) |

### 1.2 순서가 바뀌면 생기는 일

| 잘못된 순서/누락 | 결과 | 눈에 띄는가? |
| --- | --- | --- |
| Backward를 Forward보다 먼저 | 첫 반복: 캐시가 없어 오류(`self.x`가 None 등). 이후 반복: **이전 배치의 캐시**로 gradient 계산 | 첫 반복은 오류, 이후는 조용히 틀림 |
| Update를 Backward보다 먼저 | 이전 배치에서 계산된 grads로 갱신(한 스텝 지연). 첫 반복의 `grads`는 0으로 초기화돼 있어 갱신이 사실상 없음 `[레포 확인: network.py]` | **조용히 틀림**. 아래 실험처럼 loss는 거의 같게 줄어서 눈치채기 어렵다 |
| Loss 단계 생략 | `criterion.backward()`가 쓸 확률 캐시가 없음 | 오류 |
| Update 생략 / `lr=0` | 파라미터 불변 → loss가 ln(10) 근처에 그대로 | 곡선이 평평 |
`[실행 확인]` (독립 스크립트, 합성 데이터 1000개, SGD lr 0.1, 5 epoch의 epoch별 평균 loss)

| 변형 | epoch 1 | epoch 5 | 비고 |
| --- | --- | --- | --- |
| 올바른 순서 | 1.638 | 0.076 | |
| 직전 배치 grads로 갱신(한 스텝 지연) | 1.645 | 0.072 | 거의 같다 → 순서 오류가 loss 곡선만으로는 안 드러남 |
| `lr=0` | 2.382 | 2.381 | 파라미터 불변 |

교훈: **loss가 줄어든다고 순서가 맞다는 증명은 아니다.** 순서는 코드 읽기, 값·shape 테스트, gradient check(Day 2)로 확인한다.

### 1.3 epoch / iteration / 미니배치

| 용어 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| 미니배치 | 한 번의 업데이트에 쓰는 샘플 묶음 | `batch_size=128` → `x_batch (128, 784)` |
| iteration (step) | 미니배치 1개로 네 단계를 1회 수행 | 1 iteration = 파라미터 1회 갱신 |
| epoch | 학습 데이터를 한 바퀴 | MNIST: 60000/128 = 468 full + 96개 짜리 1개 = **469 iteration** |
| 전체 갱신 횟수 | epochs × iteration | MNIST 10 epoch = **4,690회**, Smoke(1000개)는 epoch당 8회 |

계산 확인 `[실행 확인]`: `60000//128=468`, `60000%128=96`, 올림 469, ×10=4690, `ceil(1000/128)=8`.

`iterate_minibatches` `[레포 확인]`: 호출될 때마다(= epoch마다) `rng.permutation(len(x))`으로 **전체 인덱스를
새로 섞고** `batch_size` 단위로 자른다. 마지막 배치는 `batch_size`보다 작을 수 있다(MNIST에서 96개).
`train()`은 `np.random.default_rng(seed)`를 한 번 만들어 계속 넘기므로, 같은 seed면 셔플 순서도 재현된다.

셔플 이유: 배치 구성이 매번 같으면 gradient 추정이 한쪽으로 치우칠 수 있다(예: 라벨 순 정렬 데이터).

`train()`이 반환하는 `loss_history`는 **epoch별 평균 loss**다 `[레포 확인]`. 두 가지 주의:

1. 평균은 epoch **중간 과정 전체**의 평균이다. epoch 끝 시점의 loss보다 높게 나온다(학습이 진행 중이므로).
2. 각 배치의 loss는 **그 배치를 업데이트하기 전** 파라미터로 계산된 값이다(Loss가 Update보다 앞).
   또 `np.mean(batch_losses)`는 배치 크기를 가중하지 않으므로 마지막 작은 배치도 같은 비중이다(영향은 작다).

## 2. SGD (확률적 경사하강법)

### 2.1 갱신식

$$
W \leftarrow W - \eta\,\frac{\partial L}{\partial W}
\qquad
(\eta:\text{학습률},\ L:\text{미니배치 평균 loss})
$$

- 파라미터 4개(`W1`, `b1`, `W2`, `b2`)에 같은 식을 원소별로 독립 적용한다. `Stochastic`인 이유는 60000개 전체가 아닌 미니배치 128개로 gradient를
  **추정**하기 때문이며, 출력층 gradient를 `batch_size`로 나눈 것(Day 2)은 이를 "평균 loss의 gradient"로 맞추려는 것이다.
- 의사코드(구현 방법은 직접 정할 것):

```text
SGD.update(params, grads):
    params의 모든 key에 대해
        params[key] 를 (lr × grads[key]) 만큼 감소시킨다   ← 배열 "내용"을 바꿔야 한다 (2.4절)
```

테스트가 보는 계약 `[레포 확인: tests/test_sgd.py]`: ① `W=[[1,2],[3,4]]`, grad=1, lr=0.1 → `[[0.9,1.9],[2.9,3.9]]`
② 모든 key 갱신 ③ `params["W"] is shared`(**객체 동일성**) ④ lr이 이동 거리에 반영.

### 2.2 왜 gradient의 "반대" 방향인가 — 1차 테일러 근사

파라미터를 $\Delta$만큼 움직일 때 loss 변화는 작은 $\Delta$에 대해

$$
L(W+\Delta) \approx L(W) + \nabla L(W)\cdot \Delta
$$

$\Delta=-\eta\,\nabla L$로 두면

$$
L(W+\Delta) \approx L(W) - \eta\,\|\nabla L\|^2 \ \le\ L(W)
$$

- 이동 크기가 같다면 내적 $\nabla L\cdot\Delta$를 가장 음수로 만드는 방향이 $-\nabla L$이다(코시-슈바르츠). 반대로 gradient 방향으로 가면 loss가 **증가**하므로 부호 하나(`-=` vs `+=`)가 학습을 "역학습"으로 만든다.
- 근사는 **작은** $\eta$에서만 성립한다. `[실행 확인]` (임의의 5차원 이차함수, seed 0)

| $\eta$ | 실제 loss 변화 | 근사 예측 (−η·‖g‖²) |
| --- | --- | --- |
| 0.1 | −2.7999 | −4.3432 (많이 어긋남) |
| 0.01 | −0.4189 | −0.4343 |
| 0.001 | −0.04328 | −0.04343 (거의 일치) |

즉 "항상 줄어든다"는 **$\eta$가 충분히 작을 때**의 말이다.

### 2.3 학습률의 영향

가장 단순한 $f(x)=x^2$에서 한 스텝은 $x \leftarrow (1-2\eta)\,x$이므로 $|1-2\eta|<1$이면 수렴, $\eta=1$이면 제자리, $\eta>1$이면 발산한다.
`[실행 확인]` $x_0=1$에서 10스텝 후 $x$: η=0.01→0.817(너무 느림), 0.1→0.107, 0.5→0.0, 0.9→0.107(부호가 번갈아 진동하며 수렴),
1.0→1.0(제자리), 1.1→6.19(발산). 신경망에서는 곡률이 방향마다 달라 가장 가파른 방향이 "안전한 η 상한"을 정한다.
너무 작으면 곡선이 매우 완만하고, 너무 크면 진동하거나 큰 값으로 튀고 `nan`/`inf`가 된다.

`[참고치]` 합성 데이터(독립 스크립트, 5 epoch, 평균 loss의 epoch1 → epoch5)

| lr | 0 | 0.01 | 0.1 | 1.0 | 10 |
| --- | --- | --- | --- | --- | --- |
| loss | 2.382 → 2.381 | 2.294 → 1.573 | 1.638 → 0.076 | 0.450 → 0.003 | 9.279 → 2.030 |

이 합성 데이터는 쉬워서 lr=1.0도 잘 되지만 MNIST로 일반화하면 안 된다. lr=10은 loss가 9까지 치솟고 끝내 2.0 근처(찍기 수준)에 머물렀다. lr 탐색은 필수가 아니므로 baseline의 0.1을 쓴다.

### 2.4 제자리(in-place) 갱신이 필요한 이유

#### (1) 객체 관계 — 코드로 확인

`TwoLayerNet.__init__`은 `params` dict를 만든 뒤 **같은 배열 객체**를 `Affine`에 넘긴다 `[레포 확인: network.py]`.
Affine도 `self.W = W`로 참조만 저장한다 `[레포 확인: layers.py]`.

```text
params dict                 Affine layer
┌───────────┐               ┌──────────────┐
│ "W1" ─────┼──► [ndarray W1 (784,128)] ◄──┼── self.W
│ "b1" ─────┼──► [ndarray b1]           ◄──┼── self.b
└───────────┘               └──────────────┘
          하나의 배열을 두 이름(dict key, layer 속성)이 가리킨다
```

`[실행 확인]` 레포의 `TwoLayerNet(seed=0)`에서 `params["W1"] is affine1.W`, `id(...) == id(...)`,
`np.shares_memory(params["W1"], affine1.W)`가 모두 `True`다. 직접 재현해 보는 확인 코드(객체 관계를 보는 도구일 뿐 SGD 구현이 아니다):

```python
from network import TwoLayerNet
m = TwoLayerNet(seed=0)
print(m.params["W1"] is m.affine1.W)
```

#### (2) 두 가지 갱신 방식의 차이

일반 NumPy 데모(`[실행 확인]`):

```python
import numpy as np
a = np.zeros(3); d = {"a": a}

d["a"] -= 1                # 같은 배열의 내용을 바꾼다
print(a, d["a"] is a)      # [-1. -1. -1.] True

d["a"] = d["a"] - 1        # 새 배열을 만들어 dict key에 다시 묶는다
print(a, d["a"] is a, d["a"])   # [-1. -1. -1.] False [-2. -2. -2.]
```

- `d["a"] -= 1`은 원래 배열의 내용을 그 자리에서 바꾸고 같은 객체를 key에 다시 저장한다 → 객체 동일성 유지.
- `d["a"] = d["a"] - 1`은 **새 배열**을 만들어 key만 갈아 끼운다 → `a`를 쥔 다른 참조(= layer)는 옛 배열을 본다.

레포의 `TwoLayerNet`에 같은 일을 하면 `[실행 확인]`:

```text
[재바인딩]  params["W1"] = params["W1"] - 0.1
  params["W1"] is affine1.W            -> False
  dict의 W1 값은 변함  / layer의 W1 값은 변하지 않음
  layer 출력(x @ W + b)이 갱신 전과 완전히 동일

[제자리]    params["W1"] -= 0.1
  params["W1"] is affine1.W            -> True
  layer의 W1 값도 함께 변함
```

#### (3) "params 값은 바뀌는데 layer 출력은 그대로" 증상 해부

```text
반복 k:  Forward는 layer.W(옛 배열)로 계산 ─► 매번 같은 logits(같은 x 기준)
         grads 계산도 문제 없음 (shape 일치, gradient check도 통과)
         Update: dict 쪽에만 새 배열이 만들어짐 ─► layer는 영원히 초기 가중치
결과:    loss가 줄지 않음. model.params를 출력하면 값은 바뀌어 있어 더 헷갈림
```

- Day 2의 `gradient_check`는 `param[index] = ...`로 **제자리** 수정을 하므로 학습 전에는 정상 동작한다. 그래서
  backward가 맞아도 이 버그는 통과해 버린다.
- 탐지법: ① `tests/test_sgd.py::test_update_is_in_place`(객체 동일성 `is`) ② `test_loss_decreases_with_sgd`
  ③ `np.shares_memory(model.params["W1"], model.affine1.W)`로 직접 확인.
- `params[key] = params[key].copy()` 후 수정, 새 dict 반환 같은 우회도 같은 문제다. 원칙: **기존 배열 객체는 두고 내용만 바꾼다**.
- `model.grads`는 `backward`가 매번 새 배열로 채우는 dict라 교체돼도 괜찮다. 제자리 규칙은 **layer가 참조를 쥔 `params`**에만
  필요하다 `[레포 확인: network.py]`. 정수 배열에 float을 `-=` 하면 캐스팅 오류가 나지만 과제 params는 float64다.

#### (4) 제공된 Adam

`Adam.update`의 마지막 줄이 `params[key] -= ...`(제자리)라서 `SGD.update`가 틀려도 Adam 테스트는 통과할 수 있다 → 6절의
진단 도구. `self.m[key] = ...`는 optimizer 내부 상태라 layer와 공유되지 않으므로 새 배열을 대입해도 된다.

## 3. SGD의 한계와 개선 optimizer (6장)

### 3.1 SGD의 약점

$f(x,y)=\frac{x^2}{20}+y^2$처럼 방향마다 기울기 크기가 다른 함수에서 SGD는 가파른 방향($y$)으로 지그재그하고 완만한 방향($x$)으로 느리게 간다.

### 3.2 Momentum

$$
v \leftarrow \mu v - \eta\,\nabla L, \qquad W \leftarrow W + v \qquad(\mu\approx 0.9)
$$

- 직관: 과거 gradient가 속도 $v$에 누적된다. 같은 방향이면 가속, 부호가 번갈아 바뀌는 방향(지그재그)은 상쇄된다. 상태 $v$ 추가.

### 3.3 AdaGrad

$$
h \leftarrow h + \nabla L \odot \nabla L, \qquad
W \leftarrow W - \eta\,\frac{1}{\sqrt{h}+\varepsilon}\,\nabla L
$$

- 직관: 큰 gradient를 자주 본 원소는 학습률을 줄이는 파라미터별 적응형 학습률. 약점: $h$가 단조 증가라 유효 lr이 0으로 수렴해 멈출 수 있다(RMSProp은 $h$를 이동평균으로 바꿔 보완).

### 3.4 Adam

$$
\begin{aligned}
m &\leftarrow \beta_1 m + (1-\beta_1)\,g
&\quad \hat m &= m/(1-\beta_1^t)\\
v &\leftarrow \beta_2 v + (1-\beta_2)\,g\odot g
&\quad \hat v &= v/(1-\beta_2^t)\\
W &\leftarrow W - \eta\,\frac{\hat m}{\sqrt{\hat v}+\varepsilon}
\end{aligned}
\qquad(\beta_1=0.9,\ \beta_2=0.999,\ \varepsilon=10^{-8})
$$

- 직관: $m$은 Momentum처럼 방향의 이동평균, $v$는 RMSProp/AdaGrad처럼 크기(제곱)의 이동평균.
  $\hat m/\sqrt{\hat v}$는 "방향 ÷ 크기"라 gradient의 절대 규모에 둔감한 보폭이 나온다.
- 편향 보정 $1/(1-\beta^t)$: $m,v$를 0으로 시작하므로 초기 몇 스텝은 0쪽으로 치우친다. 이를 보정한다.

#### 제공된 `Adam` 코드와 수식 대응 `[레포 확인: src/optimizers.py]`

| 코드 | 수식 |
| --- | --- |
| `self.m[key] = np.zeros_like(param)` (처음 호출 시) | $m_0 = 0,\ v_0 = 0$ (파라미터와 같은 shape) |
| `self.t += 1` | 스텝 수 $t$ |
| `bias1 = 1.0 - self.beta1 ** self.t` | $1-\beta_1^t$ |
| `self.m[key] = self.beta1 * self.m[key] + (1 - self.beta1) * grad` | $m \leftarrow \beta_1 m + (1-\beta_1)g$ |
| `self.v[key] = self.beta2 * self.v[key] + (1 - self.beta2) * (grad * grad)` | $v \leftarrow \beta_2 v + (1-\beta_2)g^2$ |
| `m_hat = self.m[key] / bias1`, `v_hat = self.v[key] / bias2` | $\hat m,\ \hat v$ |
| `params[key] -= self.lr * m_hat / (np.sqrt(v_hat) + self.eps)` | $W \leftarrow W-\eta\hat m/(\sqrt{\hat v}+\varepsilon)$ |

관찰할 점: ① 마지막 줄이 `-=`(제자리)라 layer와의 공유가 유지된다. ② `eps`는 `sqrt` 바깥에서 더해진다. ③ 기본 `lr=0.001`로 SGD의 0.1과
스케일이 다르다(Smoke도 Adam 0.001, SGD 0.1). ④ `[실행 확인]` 첫 스텝($t=1$)은 $\hat m=g,\hat v=g^2$이라 이동량이
$\approx\eta\,\text{sign}(g)$: grads `[0.3, -40, 0.001]`에 이동량 `[-0.001, +0.001, -0.00099999]`로 grad 크기에 거의 무관하다.

### 3.5 비교

| | SGD | Momentum | AdaGrad | Adam |
| --- | --- | --- | --- | --- |
| 갱신 아이디어 | 현재 gradient | gradient 누적(속도) | 제곱 누적으로 원소별 lr 감소 | 1·2차 모멘트 이동평균 + 편향 보정 |
| 추가 상태 | 없음 | $v$ | $h$ | $m, v, t$ |
| 하이퍼파라미터 | $\eta$ | $\eta,\mu$ | $\eta$ | $\eta,\beta_1,\beta_2,\varepsilon$ |
| 장점 | 단순, 가볍다, 이해 쉬움 | 지그재그 완화, 평탄 구간 가속 | 파라미터별 보폭, 희소 gradient에 유리 | 초기 lr 선택에 덜 민감, 널리 쓰임 |
| 단점 | 비등방 함수에서 느림, lr 민감 | $\mu$ 추가 튜닝 | lr이 계속 줄어 멈출 수 있음 | 상태 메모리·연산 증가, 상황에 따라 SGD가 일반화가 나은 경우도 있음 `[참고치]` |

레포 `optimizers.py`에는 `SGD`(구현 대상)와 `Adam`(제공)만 있고 Momentum/AdaGrad는 없다 `[레포 확인]`.

`[실행 확인]` 장난감 문제 $f=\frac{x^2}{20}+y^2$, 시작 $(-7,2)$, 30스텝. **하이퍼파라미터를 손으로 맞춘 값이라

| --- | --- | --- |

## 4. 가중치 초기화

### 4.1 0으로 초기화하면 안 되는 이유 — 대칭성

모든 가중치가 같으면 같은 층의 뉴런들이 똑같이 반응하고 똑같은 gradient로 영원히 똑같이 갱신된다(뉴런 128개가 사실상 1개).
ReLU와 0 초기화가 만나면 gradient가 아예 흐르지 않는다.

```text
W1=0, b1=0 → a1=0 → h=ReLU(0)=0 → logits=b2 (입력과 무관)
dW2 = hᵀ·dlogits = 0 (h=0),  dh = dlogits·W2ᵀ = 0 (W2=0) → dW1 = db1 = 0   ⇒ 학습되는 것은 b2뿐
```

`[실행 확인]` (독립 스크립트, 합성 데이터, 모든 파라미터 0, SGD 0.1, 5 epoch)

- loss: 2.303 → 2.301 (ln 10 = 2.3026 근처에서 정체), 정확도 약 10.9%(찍기 수준)
- 학습 후 `W1`, `W2`의 최대 절댓값 = 0.0, `b2`만 값이 생김.
- 모든 가중치를 같은 상수(0.01)로 두면: 학습 후에도 `W1`의 모든 열이 동일, `W2`의 모든 행이 동일 → 대칭이 끝까지 유지,
  정확도 약 10.4%.

해결: **무작위** 초기화로 대칭을 깨고, 그 **분산**을 층 크기에 맞춘다. bias는 0이어도 된다(대칭은 W가 깨므로).

### 4.2 Xavier vs He

층 출력 $z=\sum_{i=1}^{n} w_i x_i$에서 $w,x$가 독립이고 평균 0이면
$\mathrm{Var}(z)=n\,\mathrm{Var}(w)\,E[x^2]$. 층을 지나도 분산이 유지되려면 $n\,\mathrm{Var}(w)\,E[x^2]=\mathrm{Var}(x)$.

| | 가정 | 가중치 표준편차 | 쓰임 |
| --- | --- | --- | --- |
| Xavier(Glorot) | 활성화가 0 근처에서 거의 선형(sigmoid, tanh) → $E[x^2]=\mathrm{Var}(x)$ | $\sqrt{1/n}$ (원 논문은 $\sqrt{2/(n_{in}+n_{out})}$ 변형도 있음) | sigmoid/tanh |
| He | ReLU는 음수 절반을 0으로 → $E[x^2]\approx\tfrac12\mathrm{Var}(z_{prev})$ | $\sqrt{2/n}$ | ReLU |

즉 ReLU는 출력 분산을 절반으로 줄이므로, 그만큼 보상하려면 가중치 분산을 **2배**($2/n$) 해야 한다.
($n$은 입력 쪽 뉴런 수 = 가중치 행렬의 행 수.)

### 4.3 활성값 분포 직관

`[실행 확인]` 입력 $N(0,1)$ 1000개, 은닉 100뉴런 × 5층 ReLU, 층별 활성값 표준편차:

| 초기화 | 1층 | 2층 | 3층 | 4층 | 5층 | 해석 |
| --- | --- | --- | --- | --- | --- | --- |
| 모두 0 | 0 | 0 | 0 | 0 | 0 | 죽은 신호 |
| N(0, 1) | 5.89 | 41.7 | 295 | 1.95e+03 | 1.36e+04 | 층마다 ≈7배 폭발 |
| N(0, 0.01²) | 0.059 | 0.0042 | 3.0e-4 | 2.0e-5 | 1.4e-6 | 소실 |
| Xavier √(1/n) | 0.589 | 0.417 | 0.295 | 0.195 | 0.136 | ReLU에선 층마다 ≈√½ ≈ 0.71배씩 감소 |
| He √(2/n) | 0.832 | 0.834 | 0.834 | 0.779 | 0.768 | 거의 유지 |

- 폭발하면 softmax가 포화돼 초기 학습이 불안정하고, 소실되면 gradient도 층을 거치며 작아져 학습이 멈춘다. Xavier의 0.71배/층 감소가 4.2절의
  "분산 절반" 논리를 숫자로 보여준다. (장난감 100×100 실험이며, 층이 하나뿐인 과제 신경망은 영향이 작다.)

### 4.4 과제 `network.py`와 연결 `[레포 확인: network.py]`

```python
"W1": rng.standard_normal((input_size, hidden_size)) * np.sqrt(2.0 / input_size),   # (784,128), √(2/784)
"b1": np.zeros(hidden_size),
"W2": rng.standard_normal((hidden_size, output_size)) * np.sqrt(2.0 / hidden_size), # (128,10),  √(2/128)
"b2": np.zeros(output_size),
```

- $n$ = 각 가중치의 **행 수**(입력 차원): W1은 784, W2는 128. `[실행 확인]` 실제 표준편차 `W1: 0.0505`(= √(2/784)=0.0505),
  `W2: 0.1258`(√(2/128)=0.125).
- `np.random.default_rng(seed)`를 쓰므로 같은 seed면 같은 초기값 — 실험 비교·디버깅 재현성에 중요하다.
- 초기 loss: He 초기화의 logits는 조금씩 달라 ln(10)=2.3026과 정확히 같지 않고 2.0~2.8이면 정상
  `[과제 문서 Day 1]`. 합성 데이터에서 독립 스크립트로 `lr=0` 1 epoch 평균 loss ≈ 2.38 `[실행 확인]`.
  `test_first_loss_is_near_log_num_classes`가 바로 이 범위를 검사한다.

## 5. 배치 정규화·과적합·가중치 감소·드롭아웃·하이퍼파라미터 (필수 범위 밖)

> 과제 문서 9장: baseline은 BatchNorm/Dropout 없이 고정이며, 이들은 **필수 구현·필수 실험이 아니다**.
> 아래는 6장의 나머지 개념을 연결해 이해하기 위한 간단 정리다.

### 5.1 배치 정규화 (BatchNorm)

- 미니배치의 각 feature를 평균 0, 분산 1로 맞춘 뒤 학습 가능한 $\gamma,\beta$로 스케일·이동:
  $\hat x=(x-\mu_B)/\sqrt{\sigma_B^2+\varepsilon},\ y=\gamma\hat x+\beta$. 효과: 활성값 분포 안정, 큰 학습률 허용, 초기값 둔감.
- **train/test 차이** `[레포 확인: layers.py]`: 학습 시 현재 배치의 $\mu,\sigma^2$를 쓰며 `running_mean/var`를 이동평균
  (`momentum=0.9`)으로 갱신하고, 추론 시에는 이 running 통계를 쓴다. `[실행 확인]` 평균 5·표준편차 3 데이터로 100번 학습
  호출 후 `running_mean ≈ 5`, `running_var ≈ 9`.
- `TwoLayerNet(use_batchnorm=True)`면 Affine1 뒤에 삽입되고 `gamma1/beta1`이 `params`에 추가된다.

### 5.2 과적합과 가중치 감소

- 과적합: 학습 데이터에는 잘 맞고 처음 보는 데이터에서 성능이 떨어지는 현상(train 정확도 ≫ test 정확도). **loss 감소 ≠ 일반화** —
  loss는 학습 데이터에서 잰 값이다(`selfcheck --day 3` 질문 3번).
- 가중치 감소(L2): $L_{total}=L+\frac{\lambda}{2}\sum W^2$이므로 gradient에 $\lambda W$가 더해져 큰 가중치를 억제한다.
  레포에는 구현이 없다(`weight_decay` 검색 결과 없음 `[레포 확인]`).

### 5.3 드롭아웃

학습 중 뉴런 출력을 확률 $p$로 0으로 만들어 특정 뉴런 의존을 줄인다. `[레포 확인: Dropout]` (inverted dropout):

| | 학습(`train=True`) | 추론(`train=False`) |
| --- | --- | --- |
| forward | `mask = (rand < keep) / keep`, `x * mask` | `x`를 그대로 반환 |
| backward | `dout * mask` | 사용 안 함 |

- 학습 때 살아남은 값을 `keep`으로 미리 나누므로 기댓값이 유지되어 추론 때 따로 스케일할 필요가 없다.
  `[실행 확인]` `drop_ratio=0.2`: mask 값은 `{0, 1.25}`, 0 비율 ≈ 0.2, 입력이 전부 1일 때 학습 출력 평균 ≈ 1.0.
- `TwoLayerNet.forward(x, train=True)`는 `train_mode_layer=True`인 layer(BatchNorm, Dropout)에만 `train`을 전달하고,
  `predict()`는 `train=False`로 호출한다. `gradient_check`는 Dropout이 켜진 모델이면 `ValueError`를 낸다(mask가 매번 달라짐).

### 5.4 하이퍼파라미터 탐색과 검증 데이터

- lr, hidden size, 규제 강도 같은 하이퍼파라미터는 학습으로 정해지지 않는 값이다. **test로 고르면** test 정보가 선택에 새어
  최종 성능이 부풀려지므로, 학습 데이터에서 검증 데이터를 떼어 비교하고 test는 마지막에 한 번만 본다.
- 요령: 격자보다 무작위, lr은 로그 스케일($10^{-3}\sim10^{0}$)에서 뽑고 짧은 epoch으로 거른 뒤 범위를 좁힌다.
- 과제 baseline은 값이 고정이라 필요 없고, 레포에도 validation 분할 코드는 없다 `[레포 확인]`.

### 6.2 6개 테스트가 확인하는 것

| 테스트 | optimizer | 확인하는 것 | 실패 시 의심 |
| --- | --- | --- | --- |
| `test_returns_loss_history_per_epoch` | Adam | `train()`이 길이 3 list(유한·양수)를 반환 | `return` 누락, `NotImplementedError` 줄 미삭제, loss가 None |

| `test_loss_decreases_with_adam` | Adam lr 0.001 | 5 epoch 후 `last < first × 0.7` | **train() 연결**(Forward/Loss/Backward) 또는 backward 오류 |

| `test_parameters_actually_change` | SGD lr 0.1 | 1 epoch 후 `W1,b1,W2,b2` **모두** 처음과 다름 | 일부 key 누락, update 미호출 |

- 마지막 epoch loss는 첫 epoch보다 낮고 0.1 안팎 이하일 것으로 기대(일반적 경향 `[참고치]`).
- 관찰 정확도: 대략 97% 전후의 높은 90%대로 알려진 범위 `[참고치]`, **목표·통과 기준 아님**. 시간은 직접 측정한 값을 기록.
- "참고치"는 이 레포에서 실행해 확인된 값이 아니다. 크게 다르면(정확도 ~10%, loss가 2.3에 정체) 8.2절 표로 간다.
- 정확도는 실행 상태 점검용이며 높이려고 튜닝하지 않는다(README·과제 문서). 학습 전/후 예측 비교(노트북 셀)는 한두 문장으로 REPORT 4절에 쓴다.

## 9. 코드 없이 답하는 자가점검 (9문항)

각 문항을 코드 없이 수식·shape·그림으로 답해 본 뒤 펼쳐서 비교한다.

<details>
<summary>1. 한 미니배치에서 Forward → Loss → Backward → Update의 순서가 이래야 하는 이유는?</summary>

각 단계가 앞 단계의 산출물을 입력으로 쓴다. Loss는 Forward의 logits가 필요, Backward는 Forward/Loss가 저장한
캐시(Affine의 입력 x, ReLU mask, softmax 확률)가 필요, Update는 Backward가 만든 grads가 필요하다. 순서가 바뀌면
오류가 나거나(캐시 없음), 더 위험하게는 **이전 배치의 캐시·grads**로 조용히 계산된다.
</details>

<details>
<summary>2. SGD가 gradient의 "반대" 방향으로 가는 이유를 1차 테일러 근사로 설명하라.</summary>

$L(W+\Delta)\approx L(W)+\nabla L\cdot\Delta$. 이동 크기가 같다면 내적이 가장 작은(가장 음수) 방향이
$\Delta=-\eta\nabla L$이고, 이때 변화량은 $-\eta\|\nabla L\|^2\le0$이다. 단, 근사는 $\eta$가 작을 때만 맞다.
</details>

<details>
<summary>3. SGD가 파라미터를 제자리에서 갱신해야 하는 이유와, 어기면 나타나는 증상은?</summary>

`TwoLayerNet`의 `params["W1"]`과 `affine1.W`는 **같은 배열 객체**다. 새 배열을 key에 다시 대입하면 dict만 새
배열을 보고 layer는 옛 배열을 계속 쓴다. 증상: gradient/shape는 정상, `params` 값은 바뀌는데 layer 출력과 loss는
그대로(학습이 안 됨). `is` 또는 `np.shares_memory`로 확인한다.
</details>

<details>
<summary>4. 학습률이 너무 작을 때/너무 클 때 loss 곡선이 각각 어떻게 보이는가? $f=x^2$ 예로 설명하라.</summary>

$x\leftarrow(1-2\eta)x$. $|1-2\eta|<1$이면 수렴(작을수록 느림, 완만한 감소), $\eta>1$이면 매 스텝 $|x|$가
커져 발산(loss가 커지고 `nan`/`inf` 가능). 중간 영역에서 $\eta$가 크면 부호가 번갈아 진동하며 수렴할 수도 있다.
</details>

<details>
<summary>5. 가중치를 모두 0으로 초기화하면 이 2층 신경망에서 왜 학습이 안 되는가?</summary>

$W_1=0\Rightarrow h=0$이므로 $dW_2=h^T d\text{logits}=0$이고, $W_2=0$이라 $dh=d\text{logits}\,W_2^T=0\Rightarrow dW_1=0$이다.
갱신이 가능한 것은 $b_2$뿐이며 입력과 무관하게 같은 값을 출력한다. (0이 아닌 같은 상수여도 은닉 뉴런들이 영원히 똑같이
움직이는 대칭 문제가 있다.)
</details>

<details>
<summary>6. ReLU 신경망에서 He 초기화가 $\sqrt{2/n}$인 이유는? Xavier와 무엇이 다른가?</summary>

층 출력 분산은 $n\,\mathrm{Var}(w)\,E[x^2]$. ReLU는 음수 절반을 0으로 만들어 다음 층 입력의 $E[x^2]$가 대략
절반이 되므로, 분산 유지에 $\mathrm{Var}(w)=2/n$이 필요하다. Xavier($1/n$)는 선형에 가까운 활성화(sigmoid/tanh)를 가정해
ReLU에서는 층마다 활성값이 약 0.71배씩 줄어든다.
</details>

<details>
<summary>7. Momentum, AdaGrad, Adam은 SGD의 어떤 약점을 각각 어떻게 보완하는가?</summary>

Momentum: gradient를 속도로 누적해 지그재그를 상쇄하고 평탄 구간을 가속. AdaGrad: gradient 제곱 누적으로 원소별
학습률을 줄여 보폭을 맞춤(대신 lr이 계속 줄어 멈출 수 있음). Adam: 1차(방향)·2차(크기) 모멘트의 이동평균과
편향 보정으로 둘의 장점을 결합. 첫 스텝 이동량이 $\approx\eta\cdot\text{sign}(g)$로 gradient 절대 크기에 둔감하다.
</details>

<details>
<summary>8. Dropout은 학습 시와 추론 시에 어떻게 다르게 동작하고, 이 과제 코드에서 그 차이는 어디서 정해지는가?</summary>

학습 시 뉴런 출력의 일부를 0으로 만들고 살아남은 값을 keep 비율로 나눈다(inverted dropout). 추론 시 입력을 그대로
통과시킨다. `TwoLayerNet.forward(x, train=...)`가 `train_mode_layer=True`인 layer(BatchNorm, Dropout)에만 `train`을
전달하며, 학습 루프는 `train=True`, `predict`는 `train=False`를 쓴다. 기본 baseline에는 둘 다 꺼져 있다.
</details>

<details>
<summary>9. loss가 계속 감소하는데도 일반화 성능이 좋다고 말할 수 없는 이유는? 하이퍼파라미터를 test 데이터로 고르면 안 되는 이유는?</summary>

loss는 학습 데이터에서 잰 값이라 암기(과적합)로도 줄어든다. 일반화는 보지 못한 데이터에서 따로 확인해야 한다.
test로 하이퍼파라미터를 고르면 test 정보가 선택에 새어 들어가 최종 성능이 낙관적으로 편향되므로, 학습 데이터에서 떼어낸
검증 데이터로 고르고 test는 마지막에 한 번만 본다.
</details>
