## 한 장으로 보는 전체 흐름

```text
            Forward (Day 1, 문서 02)                         Backward (Day 2, 문서 03)
x (B,784) ─Affine1─> (B,128) ─ReLU─> (B,128) ─Affine2─> logits (B,10) ─SoftmaxWithLoss─> loss (scalar)
   dx (B,784) <─ dW1 (784,128), db1 (128,) <─ mask <─ dx2 (B,128) <─ dW2 (128,10), db2 (10,) <─ dlogits = (p - onehot)/B

Update (Day 3, 문서 04):  param -= lr * grad   (모든 param에 대해, 제자리 갱신, param.shape == grad.shape)
파라미터 수: 784*128 + 128 + 128*10 + 10 = 101,770
```

## 문서 간 핵심 연결고리

- **forward에서 저장하는 값 = backward의 재료**: `Affine.x`는 `dW`에, `ReLU.mask`는 gradient 차단에, `SoftmaxWithLoss.y_prob`·`y_true`는 `dlogits`에 쓰인다 (02 → 03).
- **`np.clip` vs `log(p+1e-7)`**: Day 1 테스트는 둘 다 통과하지만 Day 2 gradient check에서 차이가 난다 (02 → 03 실험).
- **제자리 갱신**: 01의 1.9절(`W -= x`와 `W = W - x`의 차이)이 04의 "params 값은 바뀌는데 layer 출력은 그대로" 증상으로 이어진다 (01 → 04).
- **`/B`의 의미**: loss를 배치 평균으로 정의했기 때문에 생긴다 (02) → gradient 크기가 배치 크기와 상관없어진다 (03) → 같은 학습률이 안정적으로 동작한다 (04).
