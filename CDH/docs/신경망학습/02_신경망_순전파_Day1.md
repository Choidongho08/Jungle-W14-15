## 1. 퍼셉트론에서 신경망으로

### 1.1 뉴런 하나가 하는 일

뉴런 하나의 계산은 **두 단계**다.

```text
a = w1*x1 + w2*x2 + ... + wn*xn + b        (가중합: 선형)
y = h(a)                                   (활성화 함수: 보통 비선형)
```

- **퍼셉트론**: `h`가 계단 함수. 가중치 `w`, `b`를 사람이 정해 줘야 한다(AND/OR 게이트 같은 예).
- **신경망**: `h`를 매끄러운 함수로 바꾸고, `w`, `b`를 **데이터로 학습**한다. 이 "학습"이 Day 2~3의 주제다.
- "2층 신경망"은 **가중치를 가진 층의 수**로 센다. 이 과제는 `Affine(784->128)`, `Affine(128->10)` 두 개라서 2층이다. ReLU는 파라미터가 없으므로 층 수에 넣지 않는다.

### 1.2 활성화 함수 세 가지

| 함수 | 식 | x = -2, 0, 3 일 때 | 특징 |
| --- | --- | --- | --- |
| 계단 | `1 (x>0), 0 (그 외)` | 0, 0, 1 | 출력이 0/1로 끊긴다. 거의 모든 점에서 기울기가 0이라 학습 신호를 못 준다 |
| 시그모이드 | `1 / (1 + e^{-x})` | 0.1192, 0.5, 0.9526 | 매끄럽고 출력이 (0,1). 양끝에서 기울기가 거의 0 |
| ReLU | `max(0, x)` | 0, 0, 3 | 계산이 가장 싸다. 양수 구간 기울기가 1이라 깊어져도 신호가 잘 전달된다 |

(값은 numpy로 직접 계산.) 이 과제는 **ReLU만** 쓴다.

### 1.3 왜 비선형이 꼭 필요한가

층 두 개를 **활성화 없이** 이으면 다음과 같다.

```text
z = x W1 + b1
y = z W2 + b2 = (x W1 + b1) W2 + b2 = x (W1 W2) + (b1 W2 + b2)
```

결국 `x (W') + b'` — **하나의 Affine과 똑같다.** 몇 층을 쌓아도 표현력이 늘지 않는다.
(`(x @ A) @ B == x @ (A @ B)`가 성립함을 임의의 난수 행렬로 확인했다: `True`.)

ReLU가 두 Affine 사이에 끼어야 "구부러진" 경계를 만들 수 있다.

## 2. 배열과 행렬곱으로 보는 층 계산

### 2.1 행 벡터 규약: `y = x @ W + b`

이 레포의 Affine은 `y = x @ W + b` 형태다(`layers.py` docstring). **샘플이 행**이고 **feature가 열**이다.

```text
x : (B, in)     B = batch size
W : (in, out)   열 하나가 "출력 뉴런 하나"가 쓰는 가중치 묶음
b : (out,)      출력 뉴런마다 편향 하나
y : (B, out)
```

행렬곱 규칙: 앞 행렬의 **열 수 = 뒤 행렬의 행 수**, 결과는 `(앞의 행, 뒤의 열)`. `(B, in) @ (in, out) -> (B, out)`. 이 과제의 테스트는 모두 `x @ W + b` 기준이다(`W @ x`로 쓰는 책 식과 구분).

### 2.2 bias broadcasting

`x @ W`는 `(B, out)`, `b`는 `(out,)`다. numpy는 shape를 **오른쪽부터** 맞춰 비교하고, 없는 앞 축은 1로 간주해서 늘린다.

```text
(B, out)
(   out)   ->  (1, out)  ->  모든 행에 같은 b가 더해짐
```

이것이 `test_forward_bias_is_added_to_every_row`가 검사하는 내용이다: `W`가 전부 0이면 출력의 모든 행이 `b`와 같아야 한다.

## 3. 이 과제의 shape 흐름

### 3.1 표

`B`는 배치 크기(기본 128), hidden = 128이다.

| 단계 | 연산 | 입력 shape | 파라미터 shape | 출력 shape | 코드에서의 위치 |
| --- | --- | --- | --- | --- | --- |
| 입력 | 28x28 -> 펼침 | | | `x`: (B, 784) | `load_mnist()` |
| Affine 1 | `x @ W1 + b1` | (B, 784) | W1 (784,128), b1 (128,) | (B, 128) | `affine1.forward` |
| ReLU | `max(0, .)` | (B, 128) | 없음 | (B, 128) | `ReLU.forward` |
| Affine 2 | `h @ W2 + b2` | (B, 128) | W2 (128,10), b2 (10,) | **logits**: (B, 10) | `affine2.forward` |
| Softmax | 행별 정규화 | (B, 10) | 없음 | **prob**: (B, 10) | `SoftmaxWithLoss.forward` 내부 |
| Cross Entropy | 정답 확률의 -log 평균 | prob (B,10), y (B,) | 없음 | **loss**: 스칼라 | `SoftmaxWithLoss.forward` 반환값 |

파라미터 수: `784*128 + 128 + 128*10 + 10 = 101,770`개(계산으로 확인).

### 3.2 다이어그램

```text
        이미지 28x28
            | 펼치기 + /255
            v
     x   (B, 784)
            |
            |  @ W1 (784,128)  + b1 (128,)
            v
     a1  (B, 128)
            |
            |  ReLU   (x<=0 위치를 mask 로 저장)
            v
     h   (B, 128)
            |
            |  @ W2 (128,10)   + b2 (10,)
            v
   logits (B, 10)      <-- TwoLayerNet.forward 의 반환값 (확률 아님)
            |
            |  행별 max-shift -> exp -> 행 합으로 나눔
            v
    prob  (B, 10)      <-- 각 행의 합 = 1,  self.y_prob 에 저장
            |
            |  정답 클래스 확률만 골라 -log -> 배치 평균
            v
    loss  scalar
```

모델(`TwoLayerNet`)과 손실(`SoftmaxWithLoss`)의 **경계가 logits**라는 점이 핵심이다.

### 3.3 마지막 배치는 B가 다를 수 있다

`iterate_minibatches`는 `range(0, len(x), batch_size)`로 자르므로 60000장을 128씩 자르면 468개의 128장 배치 뒤에 **96장짜리** 배치가 하나 더 나온다(`60000 - 468*128 = 96`). 그래서 코드를 "B=128"로 가정하지 말고 `logits.shape[0]` 같은 **실제 배치 크기**를 써야 한다.

## 5. 출력층: 항등 vs 소프트맥스, 그리고 logits

항등 함수(회귀용, 값을 그대로 출력)와 소프트맥스(분류용, 점수를 확률 분포로)가 출력층의 두 선택지다. 이 과제의 `affine2` 출력이 항등 함수 자리에 있고, 그 값을 **logits**라 부른다.

### 5.1 logits와 확률의 차이

| | logits | 확률 (softmax 출력) |
| --- | --- | --- |
| 범위 | 실수 전체 (음수, 1보다 큰 값 가능) | 0 ~ 1 |
| 행 합 | 제약 없음 | 정확히 1 |
| 의미 | 클래스별 "점수" | 클래스별 확신 정도 |
| 만드는 곳 | `TwoLayerNet.forward` (Affine 2) | `SoftmaxWithLoss.forward` |
| 모든 값에 같은 수를 더하면 | 값이 바뀜 | **안 바뀜** (5.3 증명) |

softmax 식:

$$
p_k = \frac{e^{a_k}}{\sum_{i=1}^{10} e^{a_i}}
$$

### 5.2 왜 모델의 출력이 logits인가 (이 과제의 설계 이유)

1. **softmax와 loss를 한 층에서 처리**해야 수치적으로 안전하다. 모델이 확률까지 만들어 버리면, loss에서 다시 `log`를 취하는 과정에서 작은 확률이 0으로 사라질 수 있다.
2. **Day 2에서 softmax와 CE를 묶으면 gradient가 단순**해진다. `losses.py` 모듈 docstring이 이 이유를 직접 적고 있다(따로 미분하면 Jacobian이 복잡). 지금은 "나중에 쓰인다"만 기억해 두면 된다.
3. **추론에는 softmax가 필요 없다.** `exp`는 단조 증가라서 큰 logit이 큰 확률이 된다. 그래서 `TwoLayerNet.predict`는 logits만 돌려주고, 숫자를 고를 때는 `argmax(logits, axis=1)`로 충분하다(`network.py` docstring).

과제 문서도 "모델의 마지막 출력은 확률이 아니라 logits"라고 명시한다(8장).

### 5.3 max-shift가 결과를 바꾸지 않는 증명

임의의 상수 `c`에 대해 분자와 분모에 같은 `e^{-c}`를 곱한다.

$$
\frac{e^{a_k}}{\sum_i e^{a_i}}
= \frac{e^{-c}\,e^{a_k}}{e^{-c}\sum_i e^{a_i}}
= \frac{e^{a_k-c}}{\sum_i e^{a_i-c}}
$$

- `c`는 **샘플(행)마다** 하나씩 고르면 된다. 한 샘플의 10개 logit에는 같은 `c`가 빠지므로 위 식이 그대로 성립한다. 다른 샘플의 `c`와는 상관이 없다.
- `c = max_i a_i`로 두면 모든 지수 `a_i - c`가 0 이하다.
  - 최댓값 항은 `e^0 = 1`이므로 분모는 **항상 1 이상** -> 0으로 나눌 일이 없다.
  - 모든 항이 `e^{(0 이하)} <= 1` -> **overflow가 없다.**
  - 다른 항이 너무 작아 0으로 underflow해도 분모에 1이 있어 결과는 정상이다.

숫자로 확인하면(float64): `np.exp(1000.)`은 `inf`(RuntimeWarning), 그대로 나누면 `inf/inf = nan`.

| logits `[1000, 1001, 1002]` | 결과 |
| --- | --- |
| shift 없이 | `[nan nan nan]` |
| 행 max(1002)를 빼면 | `[0.090031, 0.244728, 0.665241]` |
| 정답이 클래스 2일 때 loss | **0.40760596** (= 테스트의 기대값) |

`np.exp(709.)`는 `8.2e307`이고 그 위는 `inf`다(float64). float32라면 `np.exp(89)`부터 `inf`다.

### 5.4 `axis=1`과 `keepdims`

logits는 `(B, 10)`이고 softmax는 **한 샘플의 10개 클래스끼리** 정규화한다. 그러므로 모든 "행별" 연산은 클래스 축 = `axis=1` 위에서 한다.

| 연산 | 올바른 축 | 결과 shape | 비고 |
| --- | --- | --- | --- |
| 행별 최댓값 | `max(axis=1, keepdims=True)` | (B, 1) | 빼서 broadcasting |
| 행별 합 | `sum(axis=1, keepdims=True)` | (B, 1) | 나눠서 broadcasting |
| 정답 확률 고르기 | 정수 배열 인덱싱 | (B,) | 6.2 |

`keepdims=True`가 없으면 합이 `(B,)`가 된다. 이때 `(B,10) / (B,)`는 다음 두 가지 중 하나로 나쁘게 끝난다.

- `B != 10`: 끝 축이 안 맞아 `ValueError: operands could not be broadcast` (확인함: `(4,10) (4,)`)
- **`B == 10`: 에러 없이 열 방향으로 나눠서 조용히 틀린다.** `(10,10)`으로 시험해 보니 각 행의 합이 1이 아니었다(확인함). 테스트가 `B=4`라서 위의 에러만 보게 되지만, 이 함정은 알아 두자.

## 6. 교차 엔트로피 (forward 부분만)

### 6.1 정의

한 샘플에 대해, 정답 분포가 one-hot `t`이고 예측 확률이 `p`일 때:

$$
L = -\sum_{k=1}^{10} t_k \log p_k
$$

one-hot에서는 정답 클래스 `y`에서만 `t_y = 1`이고 나머지는 0이므로 합이 하나로 줄어든다.

$$
L = -\log p_y
$$

배치 `B`개의 평균을 낸 것이 최종 loss다(스칼라).

$$
\text{loss} = -\frac{1}{B}\sum_{n=1}^{B} \log p_{n,\,y_n}
$$

직관: 정답 확률 0.9면 `-log p = 0.105`, 0.1이면 `2.303`, 0.001이면 `6.908`. 정답 확률이 낮을수록 급격히 커진다.

### 6.2 정수 레이블 vs one-hot

- 정수 레이블 `(B,)`: 이 레포의 `y_true`. forward에서 정답 위치의 확률을 **직접 골라낸다.**
- one-hot `(B, 10)`: `t * log p`를 곱해 합친다. (Day 2의 `p - t`는 이 형태에서 나온 식이다.)

두 방식은 **같은 값**을 준다. 작은 예제(9장의 예제에 레이블 `[2, 1]`을 준 경우)에서 `(one_hot * log p).sum() / B`와 정수 인덱싱 평균이 모두 `5.672378...`로 일치함을 확인했다.

정수 레이블이면 `y_prob[np.arange(B), y_true]`로 `(B,)` 크기의 "정답 확률 벡터"를 만든다(`losses.py` docstring의 힌트). **인덱스 두 개를 짝지어 B개의 원소를 고르는** 방식(fancy indexing)이다. `y_prob[:, y_true]`는 `(B, B)`가 되어 틀린다.

### 6.3 `log(0)`을 피하는 두 방식: `clip` vs `+ 1e-7`

확률이 정확히 0이 되면 `log(0) = -inf`다. 두 가지 방지책이 있고 **결과가 다르다.**

| | `np.clip(p, 1e-7, 1.0)` | `log(p + 1e-7)` |
| --- | --- | --- |
| p가 정상 범위(>=1e-7) | `log p` 그대로 **정확** | `log(p + 1e-7)` — **항상 조금 틀림** |
| p = 1.0 | `-0.0` | `-1e-7` (음수 loss!) |
| p = 0.5 | 0.6931471806 | 0.6931469806 (2e-7 차이) |
| p = 0 | `-log(1e-7) = 16.118` | 16.118 |
| 의도 | 바닥만 깐다 | 모든 값을 이동시킨다 |

(표의 값은 numpy로 직접 계산.)

**왜 과제가 clip을 요구하는가 (Day 2와의 연결)**

Day 2의 `backward`는 `(p - t) / B`다. 이 식은 loss가 정확히 `-log p`일 때의 미분이다. 그런데 gradient check는 **forward가 만든 loss**를 `(loss(w+eps) - loss(w-eps)) / (2*eps)`로 수치 미분해서 이 식과 비교한다.

- `clip` 방식은 정상 확률에서 loss가 정확히 `-log p`이므로 수치 미분과 해석적 gradient가 맞는다.
- `+1e-7` 방식은 loss 자체가 `-log(p + 1e-7)`로 달라져 있다. 그 미분은 `1/p` 대신 `1/(p + 1e-7)`가 되어 **상대적으로 약 `1e-7 / p`만큼 어긋난다.** p가 0.1 근처만 돼도 1e-6 단위 상대 오차다.

작은 모의 실험(batch 6, logits 6x10 난수, 직접 numpy로 수치 미분)에서 측정한 값:

| loss 방식 | 해석적 `(p-t)/B`와의 최대 상대 오차 (gradient_check와 같은 식) |
| --- | --- |
| `clip` | 약 5.7e-9 |
| `log(p + 1e-7)` | 약 2.0e-6 |

`src/training.py`의 `gradient_check` 허용치는 `tol=1e-6`이고 위 두 번째 값은 그 위다. 즉 "Day 1 테스트는 통과하지만 Day 2에서 갑자기 실패"하는 상황이 실제로 재현된다. (과제 문서도 같은 경고를 한다. 위 수치는 **내 모의 실험**이지 레포의 `gradient_check` 실행 결과가 아니다 — 그 함수는 Day 2 구현이 있어야 돌 수 있다.)

덧붙여 Day 1 테스트는 `rtol=1e-6`이라 두 방식을 구분하지 못한다.

## 7. 초기 loss가 ln(10) 근처인 이유

### 7.1 유도

학습 전에 모든 logits가 같다고 가정하자(예: 전부 0). softmax는 같은 값끼리 같은 확률을 준다.

$$
p_k = \frac{e^{a}}{10\,e^{a}} = \frac{1}{10}
\quad\Rightarrow\quad
L = -\log\frac{1}{10} = \ln 10 \approx 2.3026
$$

정답이 몇 번이든 값이 같다. 배치 평균도 같다. `test_uniform_logits_give_log_num_classes`가 `np.zeros((8, 10))`으로 이 값을 검사한다.

의미: **"10개 중 아무거나 찍는 모델"의 loss**가 `ln 10`이다. 학습 중 loss가 이 값 위에서 시작해 내려가야 정상이다. 이 값보다 한참 위에서 시작하면 초기화나 입력 스케일이 의심스럽고, 이 값에서 안 내려가면 학습이 안 되는 것이다.

### 7.2 실제로는 왜 2.0~2.8인가

`TwoLayerNet`의 초기 logits는 정확히 같지 않고, 샘플마다 조금씩 다르다. 그 흩어짐이 loss를 `ln 10`보다 **보통 올려** 놓는다(softmax-CE는 logits가 퍼질수록 평균적으로 손해를 본다).

logits를 평균 0, 표준편차 `s`인 난수로 두면 2차 근사로

$$
E[\text{loss}] \approx \ln 10 + \frac{s^2}{2}\cdot\frac{9}{10}
$$

난수 logits 128x10을 200번 반복해 평균낸 값과 비교했다.

| s | 위 근사식 | 직접 실험 평균 |
| --- | --- | --- |
| 0 | 2.3026 | 2.3026 |
| 0.5 | 2.415 | 2.416 |
| 1.0 | 2.753 | 2.736 |
| 2.0 | (근사 부정확) | 3.752 |

과제의 "2.0~2.8" 범위는 대략 `s`가 0~1인 구간에 해당한다. 이는 위 표에서 내가 읽어 낸 해석이고, 과제 문서 자체는 범위만 제시한다.

### 7.3 He 초기화 + 합성 입력으로 본 초기 loss (실제 MNIST 아님)

`TwoLayerNet`과 같은 He 초기화 가중치(`N(0,1)*sqrt(2/fan_in)`, `b=0`)를 numpy로 만들어 **MNIST가 아닌 난수 입력**(레이블도 무작위)을 통과시켰다: 희소 난수(평균 0.075)는 logits 표준편차 0.30, 초기 loss 2.36 / 균일 난수 U(0,1)는 표준편차 0.78, 초기 loss 2.60. 둘 다 2.0~2.8 안이다. 실제 MNIST도 비슷할 것으로 **추정**하지만 **실제 MNIST로는 미검증**이다. 구현 후 `model.forward -> criterion.forward`를 한 번 돌려 직접 확인하자.

## 8. Layer 구현 포인트: 왜 저장하는가

### 8.1 Affine: 입력 `x`를 `self.x`에 저장

```text
forward 가 하는 일     : y = x @ W + b
backward (Day 2) 의 식 : dW = x.T @ dout      <- 여기에 x 가 필요
```

- `dW`는 "각 가중치가 출력에 얼마나 영향을 줬는가"이고, 그 영향의 크기는 **그 가중치에 곱해졌던 입력 x**다. forward가 끝나면 지역 변수 `x`는 사라지므로 `self.x`에 따로 남겨야 한다.
- `test_forward_saves_input_for_backward`가 이것을 검사한다: `layer.x is not None`, 값이 입력과 같아야 한다.
- 이 레포에서 `W`, `b`는 `__init__`에서 **복사하지 않고 그대로 받는다.** `TwoLayerNet.params`의 배열과 같은 객체이므로 optimizer가 `params`를 제자리에서 갱신하면 layer도 새 값을 본다(Day 3의 "제자리 갱신" 요구와 연결).
- `dx = dout @ W.T`에는 `W`가 필요하지만 W는 이미 `self.W`로 들고 있다. 그래서 저장이 필요한 것은 `x`뿐이다.
- `forward`를 부를 때마다 `self.x`가 덮어써진다. `backward`는 **직전 forward의 입력** 기준이다.

### 8.2 ReLU: `mask`를 저장, 입력은 복사본에서 수정

- 저장하는 것: `x <= 0` 위치를 나타내는 bool 배열(`x`와 같은 shape). 출력은 입력의 복사본에서 그 위치만 0으로 만든 것이다.
- backward에서 gradient는 **forward 때 살아 있던 위치(x > 0)로만** 흐르고 `x <= 0`은 막힌다. 그 위치 정보가 `mask`다. 이유는 ReLU의 미분이 `x>0`이면 1, 아니면 0이기 때문이고, 자세한 식은 Day 2에서 다룬다.
- 레포 docstring의 질문 "왜 forward의 mask를 그대로 재사용할 수 있을까?"에 대한 답: ReLU에는 학습 파라미터가 없고 **입력만으로 미분이 결정**되므로, forward에서 만든 `x <= 0` 패턴이 곧 backward가 필요로 하는 전부이다.
- 입력 `x`를 직접 수정하면 안 된다. `x`는 앞 층(`Affine`)의 출력 배열이고, 그 배열이 다른 곳에서도 쓰일 수 있다. `test_forward_does_not_modify_input`가 "입력이 바뀌지 않는다"를 검사한다.
- 경계값: `x == 0`은 **mask에 포함**(`<=`)된다. 테스트의 `[[-1,2],[0,-3]]`에서 `0`도 0으로 막힌다.
- shape는 바뀌지 않는다(`test_forward_shape`).

### 8.3 SoftmaxWithLoss: 저장할 것 두 개

저장할 것은 확률 `self.y_prob`(Day 2: `(prob - one_hot) / B`의 prob)와 정답 `self.y_true`(Day 2: 정답 위치에서 1을 빼기) 두 가지다. 테스트 `assert criterion.y_prob is not None`가 첫 번째 저장을 요구한다. `backward()`는 인자가 없으니(`def backward(self)`), 이 두 개를 forward에서 꼭 남겨야 한다.

## 9. 손으로 해 보는 작은 예제 (numpy로 확인)

### 9.1 설정

```text
x  = [[ 1,  2,  3],        shape (2, 3)     샘플 2개, feature 3개
      [-1,  0,  2]]

W1 = [[ 1, -1],            shape (3, 2)
      [ 0,  2],
      [-1,  1]]
b1 = [0.5, -1]             shape (2,)

W2 = [[ 1,  0, -1],        shape (2, 3)     클래스 3개짜리 작은 출력층
      [ 2,  1,  0]]
b2 = [0, 1, 0]             shape (3,)

정답 레이블 y = [0, 1]
```

### 9.2 손계산

**Affine 1 -> ReLU -> Affine 2** (행 하나씩 `x[행] @ W` 로 계산)

```text
행 0: [1,2,3] @ W1 = [1*1+2*0+3*(-1), 1*(-1)+2*2+3*1] = [-2, 6]   + b1 -> [-1.5, 5]
행 1: [-1,0,2] @ W1 = [-1-2, 1+2]                      = [-3, 3]   + b1 -> [-2.5, 2]

ReLU: mask(x<=0) = [[T, F],[T, F]]   ->  h = [[0, 5],
                                              [0, 2]]

행 0: [0,5] @ W2 = [10, 5, 0]   + b2 -> [10, 6, 0]
행 1: [0,2] @ W2 = [ 4, 2, 0]   + b2 -> [ 4, 3, 0]      logits shape (2, 3)
```

**Softmax (max-shift)**

| | 행 0 | 행 1 |
| --- | --- | --- |
| logits | 10, 6, 0 | 4, 3, 0 |
| 행 최댓값 c | 10 | 4 |
| a - c | 0, -4, -10 | 0, -1, -4 |
| exp(a - c) | 1, 0.018316, 0.0000454 | 1, 0.367879, 0.018316 |
| 합 | 1.018361 | 1.386195 |
| **prob** | 0.981970, 0.017985, 0.000045 | 0.721399, 0.265388, 0.013213 |

각 행의 합은 1. shift 없이 계산해도 같은 확률이 나오는 것도 확인했다(작은 값이라 overflow가 없어서 가능).

**Cross Entropy** — `y = [0, 1]`이므로 행 0은 클래스 0, 행 1은 클래스 1의 확률을 고른다.

```text
행 0: p = 0.981970  -> -ln p = 0.018195
행 1: p = 0.265388  -> -ln p = 1.326563
loss = (0.018195 + 1.326563) / 2 = 0.672379
```

(반대로 `y = [2, 1]`이면 행 0의 정답 확률이 `0.000045`라 `-ln p = 10.0182`이고 평균 loss는 `5.672379`이다. 예측이 크게 틀린 샘플 하나가 평균을 크게 올린다.)

### 9.3 numpy로 확인

손계산과 비교하는 검증용 코드다(구현 코드가 아니라 **작은 배열에서 중간값을 찍는 확인용**).

```python
import numpy as np
x  = np.array([[1., 2., 3.], [-1., 0., 2.]])
W1 = np.array([[1., -1.], [0., 2.], [-1., 1.]]);  b1 = np.array([0.5, -1.])
W2 = np.array([[1., 0., -1.], [2., 1., 0.]]);     b2 = np.array([0., 1., 0.])

a1 = x @ W1 + b1          # [[-1.5, 5.], [-2.5, 2.]]
h  = np.maximum(0, a1)    # [[0., 5.], [0., 2.]]
logits = h @ W2 + b2      # [[10., 6., 0.], [4., 3., 0.]]
print(a1, h, logits, sep="\n")
```

실행 결과(직접 돌려 확인): `a1 = [[-1.5, 5.], [-2.5, 2.]]`, `h = [[0, 5], [0, 2]]`, `logits = [[10, 6, 0], [4, 3, 0]]` — 손계산과 일치한다. 확률 `[[0.98197, 0.017985, 0.000045], [0.721399, 0.265388, 0.013213]]`, 행 합 `[1, 1]`, `y=[0,1]`일 때 loss `0.672379`도 같은 식으로 확인했다.

여러분의 `Affine.forward`, `ReLU.forward`, `SoftmaxWithLoss.forward`에 위 `x`, `W1`, ... 를 넣어 같은 값이 나오는지 보는 것이 가장 값싼 검증이다.

테스트(`tests/test_affine.py`)의 예제도 손으로 맞춰 보자: `x=[[1,2],[3,4]]`, `W=[[1,2,3],[4,5,6]]`, `b=[1,0,-1]` -> `[[10,12,14],[20,26,32]]` (행 0 열 0: `1*1 + 2*4 + 1 = 10`).

## 12. 코드 없이 답하기: 자가점검 질문

각 질문은 먼저 스스로 답을 말해 본 뒤 펼쳐 확인하자.

**Q1. `Affine.forward`는 왜 입력 `x`를 `self.x`에 저장해야 하는가?**
<details>
<summary>답</summary>

Day 2의 `dW = x.T @ dout`에 forward 때의 입력 `x`가 필요하기 때문이다. forward가 끝나면 지역 변수는 사라지므로 layer가 직접 들고 있어야 한다. `dx = dout @ W.T`의 `W`는 이미 `self.W`로 있으므로 저장할 것은 `x` 하나뿐이다.
</details>

**Q2. logits와 확률은 어떻게 다르고, 이 과제에서 모델의 마지막 출력이 logits인 이유는?**
<details>
<summary>답</summary>

logits는 클래스별 점수(실수 전체)이고, 확률은 softmax를 거쳐 0~1이며 행 합이 1이다. 모델(`TwoLayerNet`)은 logits까지만 만들고 softmax와 loss는 `SoftmaxWithLoss`가 한 층에서 처리한다. 이렇게 하면 `log`와 `exp`를 한 곳에서 안정적으로 다룰 수 있고, Day 2에서 gradient가 `(prob - one_hot) / B`로 단순해진다. 추론 때는 `argmax(logits)`만으로 충분하다(softmax가 순서를 안 바꾸므로).
</details>

**Q3. 모든 logits가 같을 때 loss가 `ln(10)`인 이유는?**
<details>
<summary>답</summary>

같은 logits는 같은 확률 `1/10`이 되고, 정답 클래스가 무엇이든 `-log(1/10) = ln 10 = 2.3026`이다. 배치 평균을 내도 같다. "10개 중 아무거나 찍는 모델"의 loss라서 학습 시작 지점의 기준선이 된다.
</details>

**Q4. 행별 max를 빼도 softmax 결과가 같은 이유를 식으로 설명하라. 왜 `axis=1`이고 `keepdims=True`인가?**
<details>
<summary>답</summary>

분자와 분모에 `e^{-c}`를 곱하면 `e^{a_k}/Σe^{a_i} = e^{a_k-c}/Σe^{a_i-c}`이다. `c`가 행마다 하나여도 그 행 안의 모든 항에 같은 값이 곱해지므로 성립한다. `c = max`로 잡으면 지수가 0 이하라 overflow가 없고 분모는 1 이상이다. 클래스 축이 `axis=1`이므로 행 단위로 max/합을 구해야 하고, `keepdims=True`로 `(B,1)`을 유지해야 `(B,10)`과 올바른 방향으로 broadcast 된다.
</details>

**Q5. 정수 레이블 `y_true: (B,)`로 정답 클래스의 확률만 어떻게 골라내며, 이것이 one-hot 곱합과 같은 값인 이유는?**
<details>
<summary>답</summary>

행 번호 `0..B-1`과 정답 열 번호 `y_true`를 짝지어 `(n, y_n)` 위치의 원소 B개를 뽑는다(fancy indexing, 결과 `(B,)`). one-hot `t`와 `log p`를 원소별로 곱해 합하면 `t_k=1`인 위치만 남으므로 정답 위치의 `log p`와 같다.
</details>

**Q6. `np.clip(p, 1e-7, 1.0)`과 `log(p + 1e-7)`는 `log(0)`을 피한다는 점은 같은데 왜 과제는 clip을 요구하는가?**
<details>
<summary>답</summary>

clip은 확률이 1e-7보다 작을 때만 개입하고 정상 범위에서는 정확한 `-log p`를 준다. `+1e-7`은 모든 확률에 적용되어 loss를 항상 약간 바꾼다. Day 2의 해석적 gradient `(p - t)/B`는 정확한 `-log p`를 전제로 하므로, `+1e-7` loss를 수치 미분하면 약 `1e-7/p` 상대 오차가 생겨 gradient check(tol 1e-6)가 실패할 수 있다. Day 1 테스트는 이 차이를 못 잡는다(rtol 1e-6, 작은 오차 허용).
</details>

**Q7. 실제 MNIST에서 학습 전 loss가 정확히 2.3026이 아니라 2.0~2.8이어도 정상인 이유는?**
<details>
<summary>답</summary>

2.3026은 모든 logits가 같을 때의 값이다. 실제 초기 모델은 He 초기화된 가중치 때문에 샘플마다 logits가 조금씩 다르다. logits가 흩어지면 평균 loss는 `ln 10`보다 보통 커지고(표준편차 s가 작을 때 대략 `ln10 + 0.45 s^2`), 샘플별로 정답 클래스가 우연히 높거나 낮게 나오므로 범위가 생긴다. 2.0~2.8은 s가 대략 0~1일 때에 해당한다. 5 이상이거나 `nan`이면 정규화/overflow를 의심한다.
</details>

**Q8. ReLU의 mask는 무엇이고 왜 forward에서 저장하며, 입력 `x`를 직접 고치면 안 되는 이유는?**
<details>
<summary>답</summary>

mask는 `x <= 0` 위치의 bool 배열이다. backward에서 gradient가 흐를 수 있는 위치(x > 0)와 막히는 위치를 알려 주는 정보라서, forward 때 만든 것을 그대로 재사용한다. 입력 배열은 앞 층의 출력일 수 있고 다른 곳에서도 쓰일 수 있으므로, 복사본을 수정해야 호출한 쪽의 값이 바뀌지 않는다.
</details>

**Q9. 학습 중 마지막 배치의 크기가 128이 아닐 수 있다. 이것이 loss 계산에서 의미하는 바는?**
<details>
<summary>답</summary>

마지막 배치는 96장이다(`60000 - 468*128`). 평균은 `128` 하드코딩이 아니라 실제 배치 크기(`logits.shape[0]`)로 내야 한다.
</details>
